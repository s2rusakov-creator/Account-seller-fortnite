# Fortnite — плашки раздевалки

Читает косметику аккаунта Fortnite и делает из неё объявление целиком: сетку
плашек, коллажи и карточку профиля на скриншоты, текст, выгрузку в CSV/JSON и
готовый оффер на GameBoost и Eldorado.

Устроено так же, как `Rasul/Account seller` для Brawl Stars, но источники данных
у Fortnite другие — и главное отличие в том, откуда берётся владение.

```bash
cd "C:\Users\Asa\PycharmProjects\IVAN\Account seller fortnite"
npm install
npm run dev
```

## Откуда данные

### Каталог косметики — `fortnite-api.com`

Один GET без ключа отдаёт всё, что когда-либо выходило в игре: **16 268
предметов**, из них 2975 скинов, 2284 кирки, 2111 эмоций, 750 планеров. У
каждого — редкость, серия, набор, сезон появления и картинки на их CDN.

Это принципиально проще, чем в Brawl Stars: там никакое API не отдаёт скины
вообще, каталог собирается из CSV-таблиц игры, а арт пришлось перечислять по
фанатской вики. Здесь всё в одном ответе.

Ответ весит 16.5 МБ, поэтому:

- он ужимается до девяти полей, которые нужны объявлению;
- держится в памяти процесса шесть часов (`src/lib/fortnite/catalog.ts`);
- **браузеру целиком не отдаётся никогда** — клиент получает только те
  предметы, которые реально есть на аккаунте;
- URL картинок не хранятся, а выводятся из id — проверено на всех 16 268
  записях, расхождений нет, экономит около 1.9 МБ на каждой копии каталога.

`npm run build:catalog` кладёт снимок каталога в `src/data/catalog-snapshot.json`.
Приложение берёт его, только если `fortnite-api.com` недоступен на холодном
старте — иначе одна их авария означала бы, что аккаунт не прочитать вообще.

### Владение — только через вход владельца

**Публичного способа посмотреть чужую раздевалку не существует.** Ни у Epic, ни
у сторонних сервисов: по нику или account ID косметику не отдаёт никто. Это
главное отличие от Brawl Stars, где `bsinfox` показывает скины просто по тегу.

Все «скин-чекеры» (fortnite.gg, fnlocker.gg и прочие) работают одинаково, и
здесь сделано так же — **device code flow**:

1. Приложение просит у Epic код и показывает его продавцу.
2. Продавец открывает `epicgames.com/activate`, входит в аккаунт, который
   продаёт, и вводит код.
3. Epic выдаёт токен, приложение читает раздевалку через `QueryProfile` — тот
   же запрос, который делает сама игра при заходе в «Раздевалку».

Что это значит на практике:

- **Пароль в приложение не попадает.** Его собирает Epic, на своём домене.
- **Токен нигде не хранится:** он создаётся, используется и убивается
  (`sessions/kill`) в пределах одного HTTP-запроса. Ни базы, ни куки, ни записи
  в лог. Поэтому чтение раздевалки происходит внутри опроса статуса входа, а не
  отдельным вызовом, которому пришлось бы токен передавать.
- Ничего не записывается в профиль — только чтение.
- Нужен доступ к аккаунту, что для продавца этого аккаунта и так выполняется.

Учётные данные клиента (`src/lib/epic/client.ts`) — игровые, много лет открыто
известны. Epic их периодически отключает: старый `fortniteIOSGameClient` сейчас
отвечает `client_disabled`, поэтому клиентов перечислено три и берётся первый
рабочий. Использование недокументированных эндпоинтов Epic — серая зона по их
пользовательскому соглашению; авторизацию даёт сам владелец аккаунта, но
понимать это стоит заранее.

## Что читается с аккаунта

Профиль `athena` — вся раздевалка: скины, рюкзаки, кирки, планеры, эмоции,
обёртки, спреи, музыка, загрузочные экраны, баннеры, плюс разблокированные
стили каждого предмета и история сезонов. Профиль `common_core` — В-Баксы.

Два места, где легко потерять данные, и как это решено:

- В профиле `athena` вперемешку с косметикой лежат квесты, XP-токены и
  служебные записи. Отбрасывается всё, чей префикс не совпадает с типом
  косметики из каталога, — новый служебный префикс в будущем сезоне отсеется
  сам, без правки кода.
- Предмет, которого нет в каталоге (вышел после последнего обновления
  каталога), **не выбрасывается**, а показывается как «Новый предмет» под своим
  id. Молча терять такие — значит занижать аккаунт.

## Выставление офферов

Адаптеры **GameBoost** (API v2) и **Eldorado** — та же схема, что в проекте по
Brawl Stars, и с теми же граблями, уже обойдёнными:

- Страницы коллажа публикуются **по одной** через `/api/collage-image`, а
  оффер уходит со ссылками. Тело запроса на Vercel ограничено 4.5 МБ — восемь
  страниц, — а полная раздевалка это два десятка; отправить их в два приёма
  тоже нельзя, второй оффер затирает картинки первого.
- **Пробный прогон** показывает точный payload с закрытыми паролями. Маскировка
  рекурсивная: GameBoost принимает креды массивом строк, и проверка
  `typeof value === 'string'` проходит мимо — в Brawl Stars это один раз
  напечатало логин и пароль продаваемого аккаунта прямо на экран.
- Цена выше 100 000 отклоняется здесь: маркетплейс на такое отвечает 500 без
  указания поля, и продавец остаётся с неудачной загрузкой и без причины.
- История загрузок (id и ссылки офферов) лежит в браузере — иначе на вопрос
  «выкладывал ли я уже этот аккаунт и куда» отвечают только два кабинета.

**Названия полей `account_data` для Fortnite не сверены.** Ключа GameBoost у
проекта нет, а схема у каждой игры своя. Сверьте один раз:
`/api/gameboost-template?slug=fortnite` — и поправьте `buildPayload`. Именно
поэтому первый прогон всегда делайте пробным.

## Если входить в Epic не хочется

«Отметить вручную» собирает список по каталогу галочками — без входа, для
случая, когда продавец не хочет логиниться на чужой машине или когда Epic
отключит очередной игровой клиент. Уровень, В-Баксы и привязки при этом
неизвестны и в объявление не попадают: выдуманное число там читается как
заявление, которое продавец не делал.

## Что на выходе

- **Сетка плашек** — карточка в цветах редкости, с артом, названием, сезоном и
  числом стилей. Фильтры по типу, редкости/серии, сезону и поиск по названию
  или набору; счётчики берутся с самого аккаунта, поэтому фильтр никогда не
  предлагает пустую категорию.
- **Коллаж** — страницы 2560×1440 по 84 плашки, WebP. PNG здесь неуместен: это
  фотографический арт, страница вышла бы под 3 МБ, а маркетплейсы столько на
  скриншот не принимают. Ник на картинке по умолчанию скрыт.
- **Текст объявления** — заголовок и описание, генерируются из состава и
  правятся руками.
- **Карточка профиля** — одна картинка на обложку объявления: лучший скин
  аккаунта крупно, цифры сбоку, редкие имена внизу. Маркетплейс показывает
  первой картинкой именно её, а стена из плашек в этой роли работает плохо.
- **Редактор скриншота** — мозаика поверх ника и почты на реальном скриншоте
  из игры. Сгенерированная картинка — это заявление, скриншот — доказательство;
  но по нику и почте аккаунт находят и пробуют вернуть после продажи.
- **Выгрузка** — CSV (точка с запятой и BOM, чтобы русский Excel открыл без
  кракозябр), JSON и простой список для переписки с покупателем.

## Что сохраняется между заходами

Последняя прочитанная раздевалка лежит в `localStorage` неделю. Без этого
перезагрузка вкладки означала бы новый код устройства и новый вход в Epic ради
списка, который не менялся, — самое раздражающее место во всём процессе.

Токен не сохраняется: к моменту, когда это выполняется, его уже нет — чтение
его убивает. Паролей автовыдачи там тоже нет, они уходят только на площадку.

## Про «редкое»

В данных Fortnite ничего не помечает недоступность: Renegade Raider — обычный
`rare`, тот же цвет, что у филлера из прошлого боевого пропуска. Поэтому
`src/lib/fortnite/notable.ts` перечисляет вручную то, на чём строится цена
(OG-скины первой главы, IKONIK, Honor Guard, Travis Scott, Floss, Take The L,
Merry Mint Axe). Эти предметы идут первыми в сетке и в коллаже и получают
золотую рамку. Без этого они тонули в трёх сотнях синих плашек — что и было
видно на первом рендере.

Список стоит пополнять по мере того, как рынок меняется, — это единственное
место в проекте, где знание рынка зашито в код.

## Проверка без аккаунта

В режиме разработки на главной есть кнопка «Открыть демо-раздевалку». Она берёт
`/api/demo`, который **собирает ответ в формате Epic и прогоняет его через
настоящий парсер** — то есть проверяет ровно тот код, который работает с
реальным аккаунтом, включая отсев служебных записей, сохранение неизвестного
предмета и суммирование В-Баксов из нескольких корзин. В продакшне маршрут
отдаёт 404, чтобы демо-данные нельзя было спутать с прочитанным аккаунтом.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Дев-сервер на порту 3000 |
| `npm run build` | Продакшн-сборка |
| `npm run typecheck` | Проверка типов |
| `npm run build:catalog` | Обновить снимок каталога |
| `npm run check` | Типы плюс сверка списков с живым каталогом |

`check:catalog` ловит то, что молча ломается: опечатку в id редкого предмета
(подсветка просто перестаёт работать) и новый тип или редкость из свежего
сезона, для которых нет названия и цвета.
