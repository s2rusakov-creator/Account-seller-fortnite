# Развёртывание

## Локально

```powershell
cd "C:\Users\Asa\PycharmProjects\IVAN\Account seller fortnite"
npm install
npm run dev
```

Переменные окружения не нужны: чтение раздевалки, каталог, коллажи и выгрузка
работают без единого ключа. Ключи нужны только для автопостинга офферов.

## На Vercel

1. Импортируйте папку как проект (фреймворк Next.js определится сам).
2. Подключите **Vercel Blob** к проекту — коллажи публикуются туда, потому что
   GameBoost принимает ссылки на картинки, а не загрузки. Подключённое
   хранилище авторизуется по OIDC и само задаёт
   `BLOB_READ_WRITE_TOKEN_STORE_ID`; отдельный токен копировать не нужно.
3. Задайте ключи площадок из `.env.example` — те, которыми будете пользоваться.
   Приложение опрашивает `/api/marketplaces` и само гасит площадку без ключа.

### Что важно знать про лимиты

- Тело запроса на Vercel — 4.5 МБ. Поэтому страницы коллажа публикуются по
  одной через `/api/collage-image`, а сам оффер уходит уже со ссылками. Не
  возвращайте картинки в тело `/api/upload`: полная раздевалка туда не влезет
  никогда.
- Чтение раздевалки — `maxDuration = 60`. Большой аккаунт плюс холодный старт
  с загрузкой каталога занимают заметно меньше, но на бесплатном плане запас
  небольшой.
- Каталог (16 268 предметов, 16.5 МБ) скачивается на холодный старт и живёт в
  памяти процесса шесть часов. На serverless это значит по загрузке на каждый
  холодный инстанс — терпимо, но если инстансы часто пересоздаются, заметно в
  трафике.

## Обновление каталога

Каталог тянется сам. Снимок для офлайн-подстраховки обновляется вручную:

```bash
npm run build:catalog
```

Раз в сезон стоит прогнать проверки — они ловят новые типы предметов и
редкости, для которых нет цвета и названия:

```bash
npm run check
```

## Чего в проде быть не должно

`/api/demo` отдаёт 404 при `NODE_ENV=production` — демо-раздевалку нельзя
спутать с прочитанным аккаунтом. Кнопка «Демо» на главной по той же причине
видна только в разработке.
